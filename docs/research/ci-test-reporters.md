# CI test reporter research

Research date: 2026-10-06

## Findings

- Flutter supports `compact`, `expanded`, `failures-only`, `github`, `json`, and `silent` reporters. `expanded` prints a separate line for each update; `failures-only` prints failing tests without passing-test progress. The example `00:50 +151: ...` is generated by this repo's explicit `--reporter=compact`; captured CI output turns each compact progress update into a log row. See [Flutter test CLI reporter definitions](https://github.com/flutter/flutter/blob/master/packages/flutter_tools/lib/src/commands/test.dart#L2663-L2688) and [the CI command builder](../../tool/changed_test_selector.dart).
- Flutter added `failures-only` and `silent` support in June 2024. The feature request specifically called out wanting failure detail without one line per success ([Flutter PR #148739](https://github.com/flutter/flutter/pull/148739)).
- OSS practice varies. Google’s Dart Labs `io_file` workflow uses `--reporter=failures-only` for both Dart tests and Flutter integration tests ([workflow](https://dart.googlesource.com/labs/+/refs/heads/main/.github/workflows/io_file.yml)). Zulip Flutter adopted a CI-only failures-only mode in February 2026 after its 3,502 passing tests generated about 3,511 lines that made failures hard to reach in GitHub Actions ([merged PR #2141](https://github.com/zulip/zulip-flutter/pull/2141)).
- Dart’s test package documents a GitHub Actions reporter as its CI default; Flutter also accepts `github`. Explicit reporter flags or `dart_test.yaml` can change that behavior ([package:test reporter docs](https://github.com/dart-lang/test/blob/master/pkgs/test/README.md), [Flutter CLI](https://github.com/flutter/flutter/blob/master/packages/flutter_tools/lib/src/commands/test.dart#L2663-L2688)).

## Recommendation

For CI, use `flutter test --reporter=failures-only`: it keeps failing-test names and failure details while removing successful-test progress. Keep the interactive default locally. Avoid `silent` when failure details are useful. This only changes test-runner reporting; build/setup and analyzer output still appear. The reporter setting does not replace application logging.

The sample’s per-test lines are not warnings or application logs; they are test progress. The current CI selector explicitly chooses `compact`, which produces these progress updates in the captured log.
