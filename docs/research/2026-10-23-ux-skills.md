# AuraVibes UX skill research and adoption

Research started: **2026-10-23T23:07:13Z**. Baseline: `e15aa6a9f`.
Scope: agent guidance only. No app UI, navigation implementation, dependencies,
plugin installation, hooks, or production changes.

## Decision

Strengthen the existing two skills, rather than install a stack of competing
design personas. Use `ux-view-clarity` for UI changes, with a short path for
small edits; use `ux-task-audit` for review-only requests. Share one conditional
interaction reference. Compose architecture, localization, accessibility, or
runtime-control guidance only when that part of the task needs it.

The user's accepted corrections identify four reusable failures: state-based
screen replacement instead of real navigation; cramped fields/actions; too
many exposed secondary controls; and screens overloaded with information.
These are feedback evidence, not a claim that this research reproduced each
defect in a running app.

## What was wrong with the guidance

- The view skill explicitly excluded local spacing and copy edits. The root
  routing rule repeated that exclusion, so precisely the affected work could
  bypass its guidance.
- The view brief covered goals and states, but lacked a navigation contract,
  an action-placement decision, and concrete form-spacing criteria.
- The audit description excluded visual-only critiques, leaving reports such
  as “these controls are cramped” or “this screen is too busy” poorly covered.
- The existing [September plan](../superpowers/specs/2026-09-27-ux-clarity-skills-plan.md)
  originally proposed loading the view skill for all visible edits. Its old
  trigger results describe prior guidance and cannot validate this patch.
- Existing UX scenarios were JSON. The user requested a different method;
  all 17 requests were migrated to Markdown with updated routing expectations,
  plus 11 failure cards. The generic harness accepts skills without JSON cases;
  no checker change or new evaluation framework is needed.

Acceptance: explicit triggers and short-path behavior; route versus local-state
rules with legitimate exceptions; control hierarchy and findable disclosure;
theme spacing and form recovery; adaptive composition with preserved context;
and verifiable review cards. No measurable outcome improvement is claimed yet.
