# Complete Stateless Engine Migration

## Goal

Make `packages/auravibes_engine` the complete app-neutral agent engine consumed by app and server: immutable inputs/outputs, deterministic decisions, request-scoped orchestration, and injected effect contracts. Engine must retain no cross-call runtime/session state, credentials, persistence, caches, pending registries, or transport lifecycle.

This is an immediate clean public-API break. Migrate all repository consumers in the same program; add no deprecated aliases or compatibility shims. Preserve existing persisted/wire formats exactly: tool names, skill slugs, JSON keys, enum strings, template serialization, and database values.

## Execution Ledger

First build change: create `.agents/plan/tasks.md`, then add the root `AGENTS.md` rule requiring its use for this migration and future non-trivial implementation.

The ledger is canonical execution state and must contain:

- Stable IDs from this plan, status (`ready`, `in_progress`, `blocked`, `done`, `cancelled`), goal, dependencies, scope, steps, and exact evidence.
- Dependency graph and current critical path.
- Compatibility/security/generated-code gates per task.
- A discovery backlog recording candidate, source task, exact paths/evidence, strict-match decision, and rejection reason.
- Exact test/check command results. `done` requires all applicable gates.
- Continuous updates before work starts, after discoveries, after implementation, and after verification.

Discovery rule: auto-promote and complete a new task before project closure only when it is app-neutral, engine-domain behavior; has no Flutter/Riverpod/Drift/app/localization/persistence/credential/UI policy; retains no cross-call state; preserves persisted/wire behavior; has bounded current callers; and needs only a minimal function/value/effect contract. Record rejected candidates. Discovery scans cover every touched file, its callers, and adjacent duplicate implementations. Project is incomplete while any initial or accepted discovered task is unfinished.

## Definition Of Complete

- Every `T00`-`T16` and every accepted discovery is `done` in `.agents/plan/tasks.md`; no unresolved strict-match candidate remains.
- Engine retains no cross-call mutable state, credentials, persistence, pending registries, caches, client/session ownership, or transport lifecycle.
- All named audit candidates now have one canonical engine implementation: skill validation/slug; tool grammar/spec/lifecycle/decisions; model capabilities/modalities; MCP normalization; context/compaction/history; URL protocol/safety/transformation; provider codecs.
- App/server own all effects and runtime state through narrow contracts; app-specific policy, UI/localization, persistence, credentials, and SDK lifecycle remain outside engine.
- Old APIs and app duplicates are deleted without compatibility shims.
- Persisted/wire fixtures remain identical; no silent metadata/status/tool-name/slug incompatibility and no unintended database migration.
- Security gates pass for URL validation, redirects, credentials, Liquid rendering, and MCP metadata.
- Focused tests, boundary checks, generation review, CI tests, and full validation pass with exact evidence in ledger.
