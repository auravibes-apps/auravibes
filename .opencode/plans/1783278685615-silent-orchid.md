# Agents Skill List Plan

## Goal

Replace the `sub_agents` app skill concept with an `agents` app skill.

- `run_sub_agent` remains a general always-on harness tool, not part of any skill.
- The `agents` skill exposes only `list_agents` for now.
- `list_agents` lists all enabled agents, not only sub-agent-visible agents.
- `list_agents` output includes which agent types each agent can serve as.
- `list_agents` accepts an optional filter for agent type.
- Create/edit/delete agent tools are out of scope for this PR.

## Existing Facts

- Package specs live in `packages/auravibes_agent/lib/src/sub_agents/sub_agent_tool_specs.dart`.
- Current skill slug constant is `subAgentsSkillSlug = 'sub_agents'`.
- `list_agents` schema currently has no inputs.
- `SubAgentRunner.listAgents()` calls `agentCatalog.listSubAgents(workspaceId)` and emits `id`, `name`, `description` only.
- App adapter `AppSubAgentCatalog.listSubAgents()` currently filters `AgentEntity.appearsInSubAgentList`.
- Agent visibility already models type-like behavior:
  - `AgentVisibility.chatSelector` means main chat only.
  - `AgentVisibility.subAgentList` means sub-agent only.
  - `AgentVisibility.both` means both main and sub-agent.
- `BuildAppSkillNativeToolSpecsUsecase` currently suppresses the old sub-agent skill for child conversations.
- `load_conversation_tool_specs_usecase.dart` already appends bare `run_sub_agent` outside skill permissions.
- `tool_approval_decision.dart` already grants `run_sub_agent` without permission lookup.

## Recommended Implementation

1. Rename the skill slug constant, not the runtime tool names.
   - In `sub_agent_tool_specs.dart`, replace the exported skill slug value with `agents`.
   - Prefer adding/renaming to `agentsSkillSlug = 'agents'` and updating app imports.
   - Keep `listAgentsToolName = 'list_agents'` and `runSubAgentToolName = 'run_sub_agent'` unchanged.
   - Keep any compatibility alias only if required to avoid wider churn inside existing uncommitted work.

2. Extend `list_agents` input schema.
   - Add optional `type` property.
   - Allowed values: `main`, `sub_agent`.
   - Keep `required: []` and `additionalProperties: false`.
   - Description: omit `type` to return all enabled agents.

3. Extend the package catalog shape minimally.
   - Add `types` to `SubAgentCatalogEntry`, as `List<String>` or equivalent package-level value.
   - Use output JSON shape:
     - `id`
     - `name`
     - `description`
     - `types`, for example `['main']`, `['sub_agent']`, or `['main', 'sub_agent']`
   - Do not use a single `type: both`; array is less lossy and still simple.

4. Make `list_agents` filterable.
   - Change `SubAgentRunner.listAgents` to accept optional arguments map, or a nullable `type` string.
   - Validate unknown `type` by returning an error JSON or an empty list; prefer error JSON so bad tool calls are visible.
   - Filter returned agents when `type` is provided.

5. Make app catalog list all enabled agents.
   - In `run_sub_agent_tool_usecase.dart`, change list implementation to include enabled agents with any visibility.
   - Map visibility to types:
     - `chatSelector` -> `['main']`
     - `subAgentList` -> `['sub_agent']`
     - `both` -> `['main', 'sub_agent']`
   - Keep `getSubAgent()` restricted to `appearsInSubAgentList`; running a sub-agent should still only accept agents that can serve as sub-agents.

6. Update app skill registration.
   - In `app_skill_registry.dart`, rename skill identifier/content/title from sub-agents to agents.
   - Native tools remain only `list_agents`.
   - Do not add create/edit/delete tools yet.

7. Update resolver/execution routing.
   - In `tool_resolver_service.dart`, map bare `list_agents` to the new `agents` skill slug.
   - Keep `run_sub_agent` execution and permission bypass working as today.
   - In `resolved_tool_service.dart`, route `skillSlug == agents` and `toolIdentifier == list_agents` to the list handler.
   - Route `run_sub_agent` independently enough that it does not depend on the `agents` skill being loaded.

8. Update localization.
   - Rename `app_skills.sub_agents` keys to `app_skills.agents` if the project expects slug-key alignment.
   - Otherwise update only visible strings if avoiding key churn is safer.
   - Run localization generation after JSON changes.

9. Update focused tests.
   - Package runner/spec test: `list_agents` schema has optional `type`; output includes `types`; filtering works.
   - App catalog test: list includes main, sub-agent, and both agents with correct types; filter works.
   - App skill native spec test: full name becomes `skill__app__agents__list_agents`.
   - Tool resolver / tool call loader tests: `list_agents` resolves under `agents` skill slug.
   - Existing `run_sub_agent` always-on and no-approval tests keep passing.
